## Why P03 cannot move

The retained 734-segment long source predates P02 word preservation and contains
no word timing. The current smart builder therefore cannot be fairly evaluated
on this artifact: a fallback segment-level regrouping would not exercise the
planned word-aware speech-turn behavior.

There is also no complete retained long smart counterpart containing
`segments_source.json`, `tts_stats.json`, and `result.json`. The analyzer records
this as `smart_long_ab.status=blocked` instead of fabricating before/after values.

P03 still needs one real long source artifact with word timing plus a smart run
on that same source, followed by the planned listening comparison.

## Why P09 cannot move

The deterministic timing counterfactual proves the allocator/rebalancer can run
collision-free over all 734 legacy windows, but it cannot prove actual runtime
overflow or tempo improvement because it does not regenerate/re-fit audio under
the current P03/P09 path.

P09 still needs a real long smart runtime receipt with overflow and tempo
distributions, plus human timing/naturalness listening A/B. No status change is
justified from retained artifacts alone.
