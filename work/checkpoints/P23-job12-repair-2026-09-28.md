## Root cause

The P13 bounded separation path calls `audio-separator` once per 15-minute window and expects each result under a temporary `output-xxxxx` directory. `audio_separator.Separator.separate()` delegates audio writing to its loaded `model_instance`. The local wrapper changed only `Separator.output_dir`, so the model writer kept the parent `stems/` directory.

Evidence from this run:

- `stems/` contains 48 non-empty vocal/instrumental window pairs (`chunk-00000` … `chunk-00047`), matching `ceil(42831.5535 / 900) = 48`.
- The first and last vocal windows probe to `900.0s` and `531.5535s`; their instrumental counterparts are also valid.
- The old top-level `stems/original_(Vocals)...flac` is only `14913.080875s`, so it is a stale/truncated artifact and must not be reused.
- The temporary directory was cleaned after failure, leaving the paths recorded by `_separator_output()` invalid. The final concat therefore raised `separation chunk is missing or empty` for `output-00000/chunk-00000...`.

This explains why the run spent the separation time producing all 48 windows but still failed before publishing the final concatenated stems manifest.

## Repair

`src/vi_dubber/separation.py` now redirects both:

1. `Separator.output_dir`, and
2. `Separator.model_instance.output_dir`

for each separation call, then restores both values in `finally`. This keeps the dependency's architecture writer and the wrapper's returned paths consistent and does not alter the short-input path or provider/execution capabilities.

The bounded path also validates both published stem files immediately after
each window. A dependency output-directory regression therefore fails at the
first affected window instead of spending the rest of the long separation run
before discovering the problem during final concat.

A regression test models the dependency behavior, verifies both directories point to the temporary output directory during separation, and verifies restoration afterwards.
